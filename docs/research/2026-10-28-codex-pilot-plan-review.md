2. **OK convention, WRONG unbounded reference call: DTW (question 2).** P:32,101–123,195 correctly maps squared local costs to `symmetric1`, then takes `sqrt(distance)`, without path-length normalisation. Python uses `window_args={"window_size": w}`, R uses `window.size=w`. **Change:** for `w=None`, select Python `window_type=None` and empty window arguments. Passing `None` as the Sakoe-Chiba width reaches a comparison against `None`. In R use `step.pattern=dtw::symmetric1` and `window.type="none"` for the unbounded case. State closed endpoints and steps `(1,0),(0,1),(1,1)` explicitly. Reject empty/nonfinite inputs and negative/noninteger windows. [Python API](https://dynamictimewarping.github.io/py-api/html/api/dtw.dtw.html), [window implementation](https://raw.githubusercontent.com/DynamicTimeWarping/dtw-python/master/dtw/window.py), [R API](https://cran.r-project.org/web/packages/dtw/refman/dtw.html).

3. **OK: both hand values (question 3).** P:108–112 is correct. For `[0,1,2]` against `[0,1,1,2]`, the zero-based path `(0,0),(1,1),(1,2),(2,3)` costs zero and is admissible with `w>=1`. For `[0,2]` against `[1]`, the only path costs `1+1=2`, giving `sqrt(2)`. **Change:** retain these literal expectations in both languages and record the first path and window condition beside them.

4. **RISK: SBD reference is suitable, edge contracts are not (questions 2,6).** P:103,130–134 matches aeon's coefficient-normalised, full-lag cross-correlation on nonzero-norm inputs with `standardize=False`. But `znorm(constant)` produces a zero vector, making the denominator zero. **Change:** reject zero-norm SBD inputs explicitly, or document a separate extension and test its literal outcomes. Do not treat aeon as an oracle for an undefined formula. The delayed-series test also needs saved inputs: fixed-length zero-padding can discard signal. For 48 ones delayed by six samples, SBD is `1-sqrt(42/48)`, approximately `0.0646`, failing `<0.05`. Use a pulse with enough zero margin and expected distance zero, and describe the boundary assumption. [aeon definition](https://www.aeon-toolkit.org/en/stable/api_reference/auto_generated/aeon.distances.sbd_distance.html).

5. **RISK: silhouette contract is mostly right but its test misses singletons (questions 2,6).** P:153–177 specifies singleton zero but only compares a fixture clustering, without guaranteeing a singleton. It also omits the `a=b=0` result and label-length validation. **Change:** derive `k` from distinct labels, validate one label per row, and explicitly return zero when both means are zero. Proposed independent case: `D=[[0,2,4],[2,0,6],[4,6,0]]`, labels `[0,0,1]`, point scores `[1/2,2/3,0]`, mean `7/18`. An all-zero matrix with those labels scores zero. Add literal invalid matrices for nonfinite entries, asymmetry, diagonal, shape and invalid cluster counts. These are course-contract checks, not claims that sklearn enforces every course restriction. [sklearn API](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.silhouette_samples.html), [singleton/zero-division implementation](https://raw.githubusercontent.com/scikit-learn/scikit-learn/main/sklearn/metrics/cluster/_unsupervised.py).

6. **WRONG: `maxclust` does not promise exactly k groups (questions 2,7).** P:152 promises labels `0..k−1`, while `fcluster(..., criterion="maxclust")` produces at most k clusters, potentially fewer at tied heights, and uses one-based labels. **Change:** either promise at most k and remap actual labels, or implement an exact-k dendrogram cut with a declared tie rule. In either case validate the actual cluster count before silhouette. [SciPy contract](https://docs.scipy.org/doc/scipy/reference/generated/scipy.cluster.hierarchy.fcluster.html).

7. **RISK, not inherently dishonest: constructed fixture (question 4).** P:83–90,159–181 is achievable in principle with sufficiently separated timing groups, distinguishable shapes and controlled perturbations. Put `mon` and `sat` in the same broad timing group so their 1.5-hour difference does not contradict the 4–6-hour group separation. Identify the compared pipelines as **raw Euclidean** versus **z-normalisation plus SBD**. Both preprocessing and comparison change. Describe the `<0.5` ratio as this pair's result, not a DTW guarantee. Use consistent units for residential and commercial profiles, rather than calling both “per household”.

Allow the local test origin, reject external requests, check failed assets, click home/lesson/previous/next links and verify theme persistence across pages and system-theme fallback. Make KaTeX parse errors fail the build and retain its accessible MathML output. [Web Storage standard](https://html.spec.whatwg.org/multipage/webstorage.html#dom-localstorage), [KaTeX API](https://katex.org/docs/api), [KaTeX options](https://katex.org/docs/options.html).
